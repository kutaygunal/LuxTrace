01The architecture: four rooms, three pipes

A script never links to the tracer. It sends sentences down a pipe, and a separate headless LuxTrace answers. That single decision is why the API works the same from the app's panel, from VS Code, or from any other language that has a pipe.

why a second process?

The interpreter boundary

Embedding Python in the C++ app would couple two release cycles and two crashing fates. A pipe sees none of that: the engine keeps running even if the script dies, and the script keeps running even if a trace is cancelled.

warm process

Start once, call many times

--serve loads Qt, OCCT and the scene registry one time. Every later call skips that floor cost: the dispatch table alone answers features in 0.04 ms.

stdout discipline

JSON and nothing else

The unwritten rule the whole design leans on: any prose a developer printed with cout would corrupt the client. Human words are exiled to stderr, where the panel log shows them in red.

03The wire: envelope anatomy

Every reply is one line. Hover a field to see why it exists.

"v":1 "seq":4 "id":5 "type":"result" "op":"run" "data":{…} "ms":8.4
v — protocol version. Bumped only when meaning changes, so a host from two years ago refuses a future binary politely instead of misreading it.
seq — position in this session's stream. Bore-sight for the log, no role in matching.
id — the matching key. The client stamps each request with an id; replies carrying another id (none should) are dropped. This is what makes interleaved progress and out-of-order work survivable.
type — result continues the session, error fails one op but the stream lives, fatal closes it with a non-zero exit.
op — echo of what you asked, so logs read as conversation.
data — the payload: metrics dicts, points arrays, scene catalogues. This is exactly the object call() hands your script.
ms — wall-clock around the dispatch, measured inside C++, free of pipe latency.
stderr side-channel — progress, warnings, the ready line. Never parsed. Displayed.

Two modes, one dispatcher

--serve · what Python uses

Interactive

One op per stdin line, one envelope per line, until EOF. A process stays warm between your calls — the geometry cache and catalogue reloads stay paid for.

{"op":"run","id":1,"params":{…}}
{"op":"optimise","id":2,"params":{…}}
--job · batch

Document in, stream out

One job file, ops run in order, one envelope each, exit 0 unless the document itself is broken. Same dispatch arms, same envelopes.

{"ops":[{"op":"features"},
  {"op":"run","params":{…}}]}

scene

Names, never indices

The registry is ordered and extensible; a saved index could silently retarget a different optic after an insert. Names survive that.

source

Real emitters

Flux in watts or lumens through the CIE V(λ) curve — which is why lux and candela exist at all. A measured ray file replaces the whole angular model.

run

The seed is the experiment

Optimise steps, sweep wiggles and tolerance yields are all functions of (config, seed). Change only the seed and you sample a different MC noise realisation.

09Internals worth knowing

process tree · from the panel

Who owns whom

LuxTrace.exe (the UI you see)
└─ QProcess: python.exe runner.py (staged script)
   └─ Popen: LuxTrace.exe --serve   ← your script talks here

Three processes, each killable by its parent. Stop button = interpreter killed; app close = the whole tree dies with it.

matching & threads

Two threads in the client, zero in your script

A reader thread pumps stdout lines into a queue so a three-minute trace can't block stderr draining (a full pipe would froze the engine). call() waits on the queue until your id shows up — other replies never wake you.

determinism

Same input, same bits

Each ray's RNG is derived from its global index and your seed — not from thread sequencing. Optimise history is a real function; tolerance yield is checkable; a reference value can be asserted to the last digit.

Design rules the protocol enforces

1 · Fail per op

error never ends the stream; the next call still answers. Batches of ten survive one typo.

2 · Ids, not order

Matching is by echoed id, never by sequence — a late reply can't desynchronise a host.

3 · Clamp, don't crash

rays=999999999, slot=42: sanitisers and range checks turn abuse into a civilised envelope.

4 · Human words are quarantined

If it isn't parseable, it goes to stderr. The parser never has to hope.

5 · Flush per line

The envelope hits the pipe the moment it exists — progress and long traces stay visible.

6 · One vocabulary

Ops, config keys, error codes: identical across --serve, --job, panel and Python. Learn it once.
