01Quick start

Three places a script can run from. In all three a client named luxtrace is already in scope — nothing to import, connect or start.

in the app

The Python tab

Edit in the panel, press Run (or Ctrl+Enter). Output streams into the log below; Stop kills the interpreter.

desktop file

The picker

python runner.py with no arguments opens a file dialog on your Desktop. Choose the script; it runs.

terminal

Direct

python runner.py myscript.py — options: --exe <path>, --job job.json, --demo, --quiet.

info = luxtrace.features()
print(info["version"], "protocol", info["protocol"])

res = luxtrace.run({"scene": {"name": "Parabolic Reflector"},
                    "run":   {"rays": 50000, "seed": 42}})
print(res["metrics"]["efficiency"])   # 0.4083 …
The one rule to remember: every call returns a plain dict — the envelope's data — or raises LuxTraceError with a machine-readable .code and a human .message.

03Operations in detail

run op: "run"

One trace of one config. The metrics object is documented in §5.

config
the config document — §4
rays · seed · threads
override the config's run{} block
export_csv
path; writes the metrics table, data carries exported_csv
res = luxtrace.run(config, rays=80000, seed=42, export_csv="out/metrics.csv")
m = res["metrics"]

sweep · sweep2d op: "sweep" / "sweep2d"

Walks one (two) of the scene's own parameters and measures any metric per point. repeats independent seeds per point are what let you tell wiggles from noise.

slot · slot_a/b
index into the scene's parameter list — see scenes()
from · to
defaults to the parameter's own min..max
steps · repeats
points on the axis; independent seeds per point
metric
an id from §5, e.g. "rms_radius_mm"
sw = luxtrace.sweep(config, slot=0, metric="rms_radius_mm", steps=8, repeats=2)
best = min(sw["points"], key=lambda p: p["value"])

sh = luxtrace.sweep2d(config, slot_a=0, slot_b=2, steps_a=6, steps_b=6, metric="efficiency")
# sh["values"][ib*len(sh["a"]) + ia] — row-major contour grid, lo..hi

optimise op: "optimise"

The tracer is deterministic, so a fixed seed makes the objective a genuine function of the parameters — which is what lets a derivative-free search converge at all.

slots
list of parameter indices the search may move
metric + goal
"maximise" | "minimise" | "target" (+ target=)
optimiser
"neldermead" (robust, 2–4 params) or "cmaes" (valleys off-axis)
evaluations
budget; default 120 — history returns every one with std-err
opt = luxtrace.optimise(config, slots=[0, 1], metric="efficiency",
                        goal="maximise", optimiser="neldermead", evaluations=25)
print("%.1f%% -> %.1f%%" % (100*opt["start_value"], 100*opt["best_value"]))
print({b["name"]: round(b["value"], 1) for b in opt["best_params"]})

tolerance op: "tolerance"

Perturbs the design many times over the tolerance distribution and reports the spread — the number a production review actually needs is yield.

tolerances[]
{"slot", "amount", "shape"} — shape: gaussian (limit=3σ), uniform, bimodal
metric · criterion
the pass gate; pass_above defaults to the metric's own direction
samples
ensemble size (200 default); same seed ⇒ same production run, checkable
tol = luxtrace.tolerance(config, metric="efficiency", criterion=0.5,
                         tolerances=[{"slot": 0, "amount": 5.0},
                                     {"slot": 1, "amount": 2.5, "shape": "uniform"}])
print("yield %.1f%%, median %.3f, p90 %.3f" % (100*tol["yield"], tol["median"], tol["p90"]))
for s in tol["sensitivity"]:
    print("  %-16s gradient %+.4f, variance share %.2f" % (s["name"], s["gradient"], s["share"]))

focus · convergence · validate

f  = luxtrace.focus(config, span_mm=30, steps=61)
print("best focus z = %.1f mm, rms %.2f mm" % (f["best_focus_mm"], f["best_rms_mm"]))

cv = luxtrace.convergence(config, min_rays=1000, max_rays=80000, points=6)
print("converged:", cv["converged"])

v  = luxtrace.validate(rays=30000)
print("%d/%d closed-form checks passed" % (v["passed_count"], len(v["cases"])))

cad · rayfile

scale=0 (default) reads millimetres out of the file's own header — the most common import mistake is something the file settles, not something you notice.

cad options
scale, axis=[0,0,1], material="N-BK7", reflective=false, quality=64, rays, seed
audit
per-part status ok / warning / bad, free edges, closed shells — in data["import"]["shapes"]
rayfile
max_rays caps an evenly-strided subset; the summary names format, flux and extent
c = luxtrace.cad("part.step", rays=20000)
print(c["import"]["format"], c["import"]["total_faces"], "faces",
      "— audit:", [sh["status"] for sh in c["import"]["shapes"]])
print("efficiency %.2f%%" % (100*c["metrics"]["efficiency"]))

r = luxtrace.rayfile("led.dat")
config["source"] = {"rayFile": "led.dat"}   # use it: overrides type/shape
print(r["summary"])

04Config reference

The same document the desktop app saves. Missing keys keep their defaults; every number arrives clamped — a two-line config is valid.

config = {
  "scene":  {"name": "Elliptical Reflector",   # exact names: luxtrace.scenes()
             "params": [200, 120, 160],          # in the order scenes() lists them
             "useDefaults": false},
  "source": {"type": "collimated",              # point | lambertian | collimated
             "shape": "disc",                   # point | disc | rect | sphere
             "spectrum": "blackbody",           # monochrome|rgb|blackbody|led|d65|table
             "wavelengthNm": 550, "cct": 5000,   # per spectrum kind
             "power": 1.0, "powerUnit": "watt",   # watt | lumen
             "halfAngleDeg": 180, "beamRadius": 25,
             "polarisation": "unpolarised",      # unpolarised|linear-s|linear-p|circular
             "rayFile": "led.dat"},
  "run":    {"rays": 100000, "threads": 0, "seed": 12345,   # 0 threads = every core
             "detectorBins": 0, "nTheta": 90, "nPhi": 72}
}

06The wire protocol — for hosts that skip Python

Any language with a pipe can drive the engine. LuxTrace.exe --serve: one operation JSON object per stdin line, one envelope per stdout line, until EOF. --job file.json: a batch document {"ops":[…]}, one envelope per op. stdout is JSON and nothing else — every human word goes to stderr.

"v":1 "seq":0 "id":7 "type":"result" "op":"run" "data":{…} "ms":8.4
v — protocol version. Bumped only when meaning changes, so an old host refuses a new binary politely instead of misreading it.
seq — position in this session's stream; for the log, not for matching.
id — the matching key: echoes whatever the request carried. Replies that do not match are dropped, not queued.
type — result continues; error fails one op, stream lives; fatal closes the stream with a non-zero exit.
op — echo of the request, so logs read as conversation.
data — the payload. Exactly the dict the Python client returns.
ms — dispatch wall-clock, measured in C++, free of pipe latency.
stderr side-channel — progress, warnings, the ready line. Never parsed; displayed.
// request  (one line on stdin)
{"id":7,"op":"run","params":{"config":{"scene":{"name":"Parabolic Reflector"}}}}
// reply    (one line on stdout)
{"v":1,"seq":0,"id":7,"type":"result","op":"run","data":{…},"ms":8.4}
// refusal  (the stream survives)
{"v":1,"seq":1,"id":8,"op":"cad","type":"error",
 "error":{"code":"import_failed","message":"cannot open nope.step"}}

07Error codes

Machine-readable codes, one per refusal — the stream continues on every one of them.

config

missing_config · bad_config

The op had no config, or the JSON was not a config document. Pass {"config":{…}}, or check for a stray comma.

vocabulary

invalid_metric · invalid_goal

Unknown metric or goal string. Use the §5 ids: efficiency, rms_radius_mm, …

bounds

invalid_slot

Parameter index outside this scene's list. scenes() knows each scene's count.

shape

empty_slots · empty_tolerances

optimise / tolerance called with nothing to vary — pass a non-empty slots[] / tolerances[].

files

missing_path · import_failed · not_traceable · load_failed · csv_write_failed

CAD and rayfile refusals; the message audits the geometry. CSV: the export path refused to open.

protocol

unknown_operation · bad_line · bad_job · bad_operation

Host-side mistakes: wrong op name, unparseable line, or a job document that is not one document with an ops array.

Client-side: LuxTraceError carries .code and .message; LuxTraceDown means the process died or timed out and carries the stderr tail for the log.

08Worked examples

Design loop — sweep, optimise, converge

cfg = {"scene": {"name": "Parabolic Reflector"}, "run": {"rays": 40000, "seed": 9}}

sw  = luxtrace.sweep(cfg, slot=0, metric="rms_radius_mm", steps=10)
z   = min(sw["points"], key=lambda p: p["value"])
cfg["scene"]["params"] = [z["parameter"], None, None]   # adopt; rest = defaults

opt = luxtrace.optimise(cfg, slots=[0, 1], metric="rms_radius_mm",
                        goal="minimise", evaluations=30)
cv  = luxtrace.convergence(cfg, min_rays=2000, max_rays=160000, points=5)
print("done:", opt["best_value"], "mm, converged:", cv["converged"])

Budget audit — where did the flux go?

res = luxtrace.run({"scene": {"name": "Light Guide (TIR)"},
                    "run":   {"rays": 120000, "seed": 1234}})
b = res["metrics"]["energy_budget"]
print("detector  %.2f%%" % (100*b["detector"]))
print("bulk abs  %.2f%%   <- Beer–Lambert, the term that scales with length"
      % (100*b["bulk_absorbed"]))
print("closed to  %.6f of the source" % b["accounted"])
Determinism. Same config + seed reproduces a result to the last digit — sweep wiggles are noise, optimiser history is a real convergence record, and a yield figure can be checked rather than quoted.
