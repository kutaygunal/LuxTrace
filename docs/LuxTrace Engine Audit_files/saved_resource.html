What is actually built

Feature inventory, derived from src/

This is not a toy. The engine already carries features that several commercial packages charge separately for: bit-reproducible Monte Carlo, two-level BVH instancing, Owen-scrambled QMC with honest replica error bars, next-event estimation, Stokes/Mueller polarisation, a characteristic-matrix coating solver, CMA-ES optimisation, Monte Carlo tolerancing with variance-share sensitivity, and IES LM-63 / EULUMDAT export. The inventory below is what a reader of the source finds, module by module.

Geometry

25 parametric scenes in a flat registry — 9 reflective (parabolic, elliptical, spherical, off-axis parabola, trough, CPC, conical concentrator, Cassegrain, corner cube), 10 refractive (ball, plano-convex, biconvex, plano-concave, half-ball, cylindrical, Fresnel, axicon, 5×5 microlens array, prism), 4 TIR (round / square / tapered guide, Porro prism), 2 scattering (integrating sphere, diffuser plate). Each declares up to four editable parameters with range, step, unit and tooltip; the last slot is always receiver position, so a focus sweep is a parameter change rather than a special case.

Closed-form derived quantities (f/#, NA, etendue, concentration ratio, paraxial focus) update as a spin box moves, without tracing.

GeometryProvider.h/.cpp · 1269 lines
CAD import

STEP, IGES and STL through OCCT's data-exchange toolkits, with a manual unit scale, a choice of illumination axis, per-face optical splitting, an auto-placed square receiver sized and centred on the part's bounding box, and a source stand-off derived from the same box. Imported geometry is a first-class SceneSetup that flows through the identical mesh → BVH → trace path as a built-in scene.

CadImport.h/.cpp
Meshing

BRepMesh_IncrementalMesh with per-surface linear and angular deflection. Per-vertex normals are read off the exact B-Rep at each tessellation node's UV parameters via BRepLProp_SLProps, falling back to area-weighted facet normals — which is what removes tessellation from the accuracy budget rather than merely reducing it. TopAbs_REVERSED faces have their winding flipped so d · n > 0 genuinely means "leaving".

MeshBuilder.cpp · Mesh.h
Acceleration

Binned surface-area-heuristic BVH — 16 bins, leaf size 4, double-precision bounds, split-axis-ordered traversal. Two-level (TLAS over rigid instance placements, BLAS per part) so a 25-lenslet array is one tessellation and one hierarchy instead of 25 of each. Static and instanced traversal are deliberately separate functions. A brute-force reference walk exists purely so tests can prove the hierarchy changes no result.

TraceScene.h/.cpp
Transport

Explicit-stack path tracer, branching at every refractive interface, depth limit 160. Möller–Trumbore, two-sided. Scale-relative epsilon (kEpsRel × coordinate magnitude) rather than an absolute one. An 8-deep medium stack with mediumPriority arbitration, so cemented doublets and immersed optics refract against the right index pair.

Rays seed their own RNG from a global index, so a run is bit-identical at any thread count — tested. Scalar totals reduce in chunk order, grids per thread; Neumaier compensated summation and Welford/Chan moments throughout.

RayTracer.cpp · 2014 lines
Surface physics

Unpolarised Fresnel with TIR; Snell with a shading-normal guard that falls back to the facet normal at silhouettes. Metals get complex-index Fresnel (Born & Wolf §13.2). Coatings in four tiers: none, ideal residual, tabulated R(λ), and an 8-layer characteristic-matrix stack. Scatter in five models: specular, GGX microfacet with Smith masking, ABg, Lambertian, and a resampled measured table — each with total-integrated-scatter and an importance-sampling weight.

Optics.h · SurfaceOptics.h · Bsdf.cpp · Coating.cpp · Material.cpp
Volume physics

Beer–Lambert bulk attenuation per medium with a scene-wide scale, and Henyey–Greenstein volume scattering with a coefficient and an asymmetry parameter — the model every white diffusing plastic in every luminaire actually needs.

Bsdf.h (bsdf::Volume) · RayTracer.cpp
Polarisation

Optional Stokes vector per branch with Mueller matrices at dielectric interfaces, amplitude Fresnel coefficients carrying phase (so TIR is a retarder), and frame rotation between successive planes of incidence. The run reports flux-weighted degree of polarisation, degree of linear polarisation and polarisation angle.

Polarisation.h/.cpp
Spectral

Six source spectra — monochromatic, stratified RGB, Planck blackbody, blue-pump LED phosphor, CIE D65, and a measured table — resolved once per run into a 256-bin inverse CDF. One wavelength per ray, so a spectral trace costs a monochromatic one. CIE V(λ) weighting at emission makes the entire result photometric without a second accumulator: watts and lumens, W/m² and lux, W/sr and candela out of a single trace. sRGB band weights, CIE 1931 XYZ and McCamy CCT for spot chromaticity.

Spectrum.h/.cpp
Estimators

Owen-scrambled Sobol (Joe–Kuo direction numbers, 8 dimensions) split into independent replicas so the reported error bar measures what QMC achieved rather than what plain Monte Carlo would have. Emission aiming at the scene's bounding sphere — exact, not merely unbiased, with a companion draw so the aimed-away light still appears in the far field. Next-event estimation to up to 8 receivers, declined by a pre-sample well-conditioning bound so the decision cannot bias the estimate. Russian roulette and branch collapsing, with every estimator residual booked to a named bucket that closes the energy balance exactly.

Sampling.h · RayTracer.cpp
Receivers

Multiple receivers, each with its own frame (centre, two in-plane axes, normal), its own bin grid and its own acceptance half-angle cone. Far-field θ/φ intensity binning with correct per-cell solid angle, azimuth-averaged profile and interpolated FWHM. Arrivals recorded by reservoir sampling (Algorithm R, chunk-seeded) carrying direction and accumulated optical path length.

SimulationResult.h · TraceScene.h (DetectorInfo)
Analysis

Spot metrics (peak / mean / min irradiance, both uniformity conventions, centroid, RMS radius, D50, D86, FWHM in x and y, chromaticity, CCT). Cross-sections and encircled energy. Through-focus by analytic propagation of stored arrivals — one trace, many planes. MTF from a line-spread function and an explicit DFT, tangential and sagittal, with a diffraction-limit reference curve. Wavefront error from per-branch OPL, with a best-fit focus so receiver defocus is not mistaken for aberration, RMS and PTV in waves, and a Maréchal Strehl gated by an honest validity test.

Where you stand against the commercial tools

Honest positioning

The gaps are narrower than the price difference suggests, and they are not evenly distributed. You are genuinely ahead on reproducibility and on the honesty of the error reporting. You are behind on source interop, on optical-property authoring, and on physical optics.

Physical accuracy

Fourteen findings · where the model stops being physics
A-01Accuracy

Polarised traces pass through mirrors unchanged

Now In the opaque branch of tracePath, reflectance comes from metalReflectance() — an unpolarised scalar. havePol is never set there, so spawn() receives a null Stokes pointer and the branch inherits the incoming state verbatim. A polarised run bouncing off an aluminium reflector reports the source's polarisation, not the mirror's.

Change Compute complex amplitude reflectances rs, rp and their phase difference from the complex index, then build a Mueller::fromFresnel exactly as the dielectric branch does. The machinery is already written and already tested; it simply is not called on this path.

Why Metal reflection is the largest single source of polarisation change in most reflective systems. Shipping a polarisation feature that ignores mirrors is worse than not shipping one.

Impact high · Effort low · src/core/RayTracer.cpp, src/core/Polarisation.cpp
A-02Accuracy

The ideal and table coating tiers use a fabricated angular roll-off

Now Coating::reflectanceSP takes the requested residual and multiplies it by angularRolloff(bare, bareAtNormal) — the bare interface's own angular shape. A real AR coating does not track bare-glass Fresnel: a V-coat rises steeply off its design angle, a broadband AR has a shallow minimum that walks with both angle and wavelength, and a high reflector's edge moves in the opposite direction.

Change Make Ideal a synthesised coating: solve for the single-layer index and thickness that produce the requested residual at the design wavelength, then evaluate it through the same characteristic-matrix path Stack already uses. All three tiers then share one solver and every angular and spectral dependence is physical by construction rather than by approximation.

Why This is the one place in the engine where a number is invented rather than derived, and it sits on every coated surface in a multi-element system.

Impact high · Effort medium · src/core/Coating.cpp
A-03Accuracy

The coating table is one-dimensional but documents itself as two

Now Coating.h describes the Table model as "measured R(lambda, theta), used as it stands", but the struct stores only lambdaNm[8] and reflectance[8]. Angle comes from the same fabricated roll-off as A-02.

Change Either store a genuine λ×θ grid with bilinear interpolation, or fix the comment. A coating vendor's data sheet is a 2D table; accepting it as one is what makes "apply the coating we actually bought" possible.

Why A header that overstates the model is how a wrong number gets trusted.

Impact medium · Effort low · src/core/Coating.h
A-04Accuracy

Coatings cannot absorb, and stacks cannot contain metal

Now layerIndex[] is real-valued, and at a coated interface transE = e - reflE — absorptance is zero by construction. Enhanced aluminium, dielectric-on-metal mirrors and any thick multilayer all have a real A = 1 − R − T.

Change Complex characteristic matrices (the complex-index arithmetic already exists for metalReflectance), and have the coating return the triple (R, T, A) with the absorbed share booked to fluxAbsorbed.

Why Without it, every coated mirror in the engine is lossless, and efficiency figures come out optimistic in exactly the systems where losses matter most.

Impact high · Effort medium · src/core/Coating.cpp, src/core/RayTracer.cpp
A-05Accuracy

Two independent scattering models run side by side

Now There are three parallel roughness/scatter paths in one interaction: the Gaussian normal tilt (perturbNormal), the Lambertian scatter fraction, and the real bsdf::Surface. The first two decide direction while energy stays whatever specular Fresnel gave it, so a rough dielectric reflects as though it were polished and then leaves in a diffuse direction.

Change Collapse to one model. Load scatter as a Lambertian bsdf::Surface with fraction = scatter, load roughness as a microfacet α, and delete both legacy branches from tracePath. Evaluate Fresnel at the sampled microfacet normal, not the smooth one.

Why Three models means three behaviours that can disagree, and the two legacy ones are the biased ones. Your own header comments already say the Gaussian tilt "is not an energy-conserving BSDF and cannot be fitted to measured data" — yet it is still the default in every built-in scene.

Impact high · Effort medium · src/core/RayTracer.cpp, src/core/GeometryProvider.cpp
A-06Accuracy

Rays rejected by a receiver's acceptance cone are booked as absorbed

Now When !det.accepts(s.d) the branch's energy goes to fluxAbsorbed and the path terminates. That light was not absorbed by anything — it was refused by a measurement condition.

Change Give it its own bucket (fluxRejected) in the energy balance, and add a per-receiver flag choosing whether a rejected ray terminates or continues. Commercial tools distinguish an absorbing receiver from a recording plane; you cannot model a photometer behind a window today.

Why An absorbed-flux figure that silently includes acceptance rejections is a wrong loss budget, and the loss budget is what the tool is for.

Impact medium · Effort low · src/core/RayTracer.cpp, src/core/SimulationResult.h
A-07Accuracy

The far field conflates escaping light with detected light

Now binDirection() is called both when a ray escapes the scene and when it lands on a receiver. The intensity grid's total is therefore fluxEscaped + fluxDetector. For a luminaire measured on a plane in front of it that is arguably right; for a scene whose receiver absorbs most of the light it makes the candela distribution mostly a picture of the receiver.

Change Make the far-field source explicit: a dedicated far-field receiver, or a three-way switch (escaping only / detected only / both) surfaced in the UI and stamped on the exported IES file. Silence here is the problem, not the choice.

Why An IES file whose definition of "emitted" is undocumented cannot be handed to a lighting consultant.

Impact medium · Effort low · src/core/RayTracer.cpp, src/core/Analysis.cpp
A-08Accuracy

Next-event estimation never fires from a volume scattering event

Now nextEventEstimate() is called only from the two surface-diffuse branches. A ray that turns inside a diffusing plastic just re-enters the random walk. That is precisely the geometry — a filled polymer over an LED — where the variance is worst and where NEE would pay most.

Change Call it from the volume-scatter branch too, with the Henyey–Greenstein phase value in place of the cosine lobe, and the same pre-sample conditioning bound.

Why Volume scattering was added as a headline feature; without NEE it is the slowest-converging thing in the engine.

Impact medium · Effort medium · src/core/RayTracer.cpp
A-09Accuracy

A medium has no scattering albedo — absorption and scattering share one coefficient family

Now bsdf::Volume::coefficient is a scattering coefficient and SurfaceOptics::absorption is a Beer–Lambert α, but they are unrelated numbers on the same medium with no albedo relating them. Real diffuser data is quoted as μs, μa and g.

Change Express the medium as (μs, μa, g) with the extinction μt = μs + μa driving the free-path draw and the single-scattering albedo driving the energy split at each event. Keep α as an import alias.

Why It is the parameterisation every measured diffuser sheet uses, so it is the difference between entering a data sheet and guessing at one.

Impact medium · Effort medium · src/core/Bsdf.h, src/core/RayTracer.cpp
A-10Accuracy

Scatter is wavelength-independent

Now Neither bsdf::Surface nor bsdf::Volume takes a wavelength. Measured ABg parameters are always quoted at a wavelength, and particulate scatter scales steeply with it.

Change Add a reference wavelength and a scaling exponent to both (λ−n, defaulting to the value the model's own literature uses). Every call site already carries ctx.lambda.

Why A spectral trace through a scattering medium currently gives every colour the same haze, which is visibly wrong for exactly the white-diffuser case the feature was built for.

Impact medium · Effort low · src/core/Bsdf.h/.cpp
A-11Accuracy

MTF, Strehl and OPD are geometric-only and not labelled as such

Now modulationTransfer() builds a line-spread function from ray arrivals and transforms it. The diffraction limit is drawn as a reference curve beside it, not folded in. At an f/8 diffraction-limited design the geometric MTF will read higher than physically achievable, and nothing on screen says so.

Change Two steps. Immediately: label the curve "geometric MTF" everywhere it appears, in the UI and in the report. Then: you already store per-arrival OPL and solve for a best-fit focus — that is a wavefront at the exit pupil, and a Fraunhofer transform of it is a genuine physical-optics PSF. Convolving the geometric spot with it gives a diffraction-inclusive MTF.

Why This is the highest-leverage physics you can add, because the input data already exists in the result. It is also the single feature that separates ray tracers from optical design tools.

Impact high · Effort high · src/core/Analysis.cpp
A-12Accuracy

No fluorescence, so a phosphor is a spectrum rather than a part

Now SpectrumConfig::LedPhosphor describes an emitter's spectrum. There is no medium that absorbs at one wavelength and re-emits at another, so a remote-phosphor plate, a quantum-dot film or a fluorescent diffuser cannot be modelled at all.

Change A conversion event in the volume model: absorption cross-section by wavelength, a quantum yield, and a Stokes-shifted emission SPD sampled isotropically. The ray keeps its energy scaled by the yield and takes a new wavelength.

Why Remote phosphor is standard practice in white-LED luminaire design, and it is a category of part your tool currently cannot represent.

Impact medium · Effort high · src/core/Bsdf.h, src/core/Spectrum.h
A-13Accuracy

The retarder Mueller matrix is implemented and never used

Now Mueller::retarder() and Mueller::polariser() exist, are correct, and have no call site in the transport code. There is no birefringent medium and no polarising element type.

Change A uniaxial medium with an optic axis, splitting a refracted branch into ordinary and extraordinary rays with accumulated retardance; and a surface type that applies polariser() directly. Stress birefringence follows from the same machinery once a stress tensor can be attached.

Why Two of the three things a polarisation feature is bought for — polarisers and waveplates — are one call site away from working.

Impact medium · Effort high · src/core/Polarisation.cpp, src/core/RayTracer.cpp
A-14Accuracy

The glass catalogue is nine entries deep

Now Vacuum, N-BK7, N-SF11, fused silica, PMMA, polycarbonate, water, aluminium, silver, gold — hard-coded as a fixed-size POD with at most eight table samples and six Sellmeier terms.

Change Keep the POD (it is the right call for the hot path) but add a loader for Schott / Ohara / CDGM catalogue files and for refractiveindex.info YAML, resolving into that same struct at load. Ten materials is a demonstration; a catalogue is a tool.

Why The first thing a lens designer does is type a glass name. If it is not there, the tool is not usable for their job, whatever else it does.

Robustness and correctness

Seven findings · what fails quietly
R-01Robustness

Surface overrides are keyed by array index, and configs persist them

Now SurfaceOverride::surface is an int index into TraceScene::surfaces(), and ConfigIO serialises it. Reopen a saved config after the scene registry changes, or against a different CAD import, and every optical edit silently lands on whatever surface now occupies that slot. The scene enum was deliberately stored by name for exactly this reason; the overrides were not.

Change Key overrides by surface label plus a stable content hash, resolving to an index at load, and report unmatched overrides instead of dropping or misapplying them.

Why This is the failure mode that produces a plausible-looking wrong answer, which is the only kind that actually costs someone money.

Impact high · Effort low · src/core/RayTracer.h, src/core/ConfigIO.cpp
R-02Robustness

Medium-stack anomalies are swallowed silently

Now MediumStack::popValue deliberately ignores an exit from a body the stack never recorded entering, and when s.medium < 0 the index pair falls back to a guess (leaving ? nSurf : 1.0). Both are the right recovery, but neither leaves a trace. A self-intersecting or non-manifold imported mesh will produce systematically wrong index pairs and a perfectly clean-looking result.

Change Count each anomaly class per run — unmatched exit, stack overflow at kMediumDepth, guessed entry index — and surface the counts in the run summary with a warning threshold. This is what a commercial tracer's ray-error report is.

Why Imported CAD is your main real-world path and the one most likely to be geometrically imperfect.

Impact high · Effort low · src/core/RayTracer.cpp
R-03Robustness

Truncated flux is reported without a reason

Now fluxTruncated collects depth-limit kills, path-stack overflows, degenerate directions and failed refractions into one number. At kMaxDepth = 160 a light guide or an integrating sphere can put real flux there, and the user has no way to know which mechanism did it or whether raising the limit would help.

Change Split into named counters, and raise a visible warning when truncated flux exceeds a fraction of the source (0.1 % is a reasonable default).

Why "Where did the missing 4 % go?" is the question the energy balance exists to answer, and right now it answers "somewhere".

Impact medium · Effort low · src/core/RayTracer.cpp
R-04Robustness

fluxRoulette is a single bucket for five different estimators

Now Russian roulette, emission aiming, next-event estimation, BSDF sampling weights and the skipDetector suppression all book their residual to the same accumulator. Its expectation is zero, so the energy balance closes — even if one contributor is systematically wrong and another cancels it.

Change One named channel per estimator, and a test asserting each channel's mean lies within its own error bar over a long run. It costs four doubles.

Why The closed energy balance is currently your strongest correctness argument, and in this one respect it can close while being wrong. Splitting the channel turns it into a real guarantee.

Impact high · Effort low · src/core/RayTracer.cpp, test/TestMain.cpp
R-05Robustness

No statistical-equivalence test guards the variance reduction

Now The tests prove determinism, thread invariance and energy conservation, but nothing asserts that turning the estimators off gives the same expectation as leaving them on. Every one of aiming, NEE, roulette and branch collapsing is a place a subtle bias could enter and never be caught.

Change For a handful of scenes with different character (specular, diffuse, TIR-heavy), run with varianceReduction and each estimator toggled, and assert the efficiencies agree within their combined 3σ.

Why This is the test that lets you change the estimator with confidence — and you will want to change it, repeatedly.

Impact high · Effort low · test/TestMain.cpp
R-06Robustness

Imported geometry is never checked for the properties the tracer assumes

Now cadimport::read() reports face counts and a bounding box. It does not check shell closedness, free edges, duplicate or degenerate triangles, or normal consistency — all of which the medium-tracking model depends on. STEP unit metadata is also ignored in favour of a manual scale factor, so the most common import mistake is left to the user to notice.

Change Run BRepCheck_Analyzer and a mesh audit at import, present a per-part traffic light in the import dialog, and read the unit from the STEP header with the manual scale as an override rather than the only mechanism. Offer ShapeFix healing for the parts that fail — TKShHealing is already linked.

Why "It traced, so the model must be fine" is the assumption that produces confidently wrong numbers on customer geometry.

Impact high · Effort medium · src/core/CadImport.cpp
R-07Robustness

No regression corpus, despite determinism making one trivial

Now The tests assert bands ("reflector efficiency between 0.78 and 0.90"). Because runs are bit-reproducible, you could assert exact reference values for all 25 scenes and detect any behavioural drift to the last digit — and you are not.

Change Store a reference result per scene at a fixed seed and ray count. Fail CI on any drift beyond a stated tolerance, with a deliberate "bless the new values" step for intended changes.

Why This is the payoff for the determinism work you have already done, and it is the artefact that makes an evaluator believe the tool. Almost no commercial tracer can offer it.

Performance

Seven findings · ordered by measured leverage
P-01Perf

Shadow rays for next-event estimation use a nearest-hit query

Now Each NEE connection calls scene.nearestHit() and then checks whether the surface found was the receiver. That walks the whole hierarchy to completion when a single occluder anywhere along the segment would have settled it.

Change Add an occluded(o, d, tMax) that returns on the first hit against anything that is not the target receiver. Standard, and it is a large fraction of the trace on exactly the scenes NEE was added for.

Why Integrating sphere and diffuser scenes fire an NEE connection at nearly every bounce.

Impact high · Effort low · src/core/TraceScene.h, src/core/RayTracer.cpp
P-02Perf

The geometry cache holds its mutex across the whole build

Now entryFor() calls buildData() — OCCT tessellation plus a full BVH build, potentially seconds — while holding SceneCache::mutex. A parameter sweep serialises every geometry build, and worse, the UI's GeometryWorker blocks behind a running study, so the 3D viewport freezes on an unrelated background job.

Change Insert an in-flight promise under the lock, release it, build outside it, then fulfil. Concurrent requests for the same key wait on the promise instead of rebuilding.

Why This is a responsiveness bug as much as a throughput one, and responsiveness is what the whole worker architecture was built to protect.

Impact high · Effort low · src/core/Simulation.cpp
P-03Perf

The BVH is built single-threaded and recursively

Now buildNode() recurses on one thread. On the 81k-triangle microlens array, and on any real CAD assembly, this is the dominant term in the latency between moving a slider and seeing geometry.

Change Spawn a task per subtree above a size threshold (a few thousand primitives) and keep the serial path below it. The node array needs a pre-sized allocation or a per-task arena, but the split logic is unchanged and the resulting tree is identical.

Why Build time is what makes parameter exploration feel sluggish, and parameter exploration is the app's core interaction.

Impact high · Effort medium · src/core/TraceScene.cpp
P-04Perf

Leaves hold four triangles and are tested one at a time

Now kLeafSize = 4 and intersectTriangle() is scalar double. The data layout is already exactly what a 4-wide AVX2 double intersection wants; it simply is not written.

Change A packed 4-triangle leaf record (v0, e1, e2 as structure-of-arrays) and an AVX2 Möller–Trumbore over all four at once, with a scalar tail. Keep the scalar path for the reference walk so the equivalence test still means something.

Why The header already documents that float bounds and 4-wide nodes were benchmarked and lost. SIMD at the leaf is the option that has not been tried, and it is the one the layout favours.

Impact medium · Effort high · src/core/TraceScene.cpp
P-05Perf

Nodes are pushed unconditionally and re-tested on pop

Now An interior node pushes both children without testing either; the box test happens on pop, clipped to best. Correct, but every node on the stack is a node that will be popped and tested even after best has tightened past it.

Change Test at push time and store the entry distance alongside the index; on pop, skip immediately when the stored entry distance is already beyond best. A well-established 10–20 % on incoherent workloads.

Impact medium · Effort low · src/core/TraceScene.cpp
P-06Perf

A thread pool is created and destroyed per trace

Now RayTracer::trace() spawns threads - 1 std::threads and joins them. A tolerance study of 200 samples at 8000 rays each pays that 200 times, and an optimisation run pays it once per evaluation — hundreds of times, against traces short enough for the spawn cost to matter.

Change A persistent pool owned by the process, with the trace submitting chunks to it. Chunk-order reduction already guarantees determinism regardless of which worker ran what, so nothing about reproducibility changes.

Impact medium · Effort medium · src/core/RayTracer.cpp
P-07Perf

Two unbounded allocations scale with threads × bins

Now Every thread holds a full copy of the all-receivers grid, and with progressive preview enabled a second copy again in its PreviewSlot. At a fine grid across several receivers on a many-core machine this is hundreds of megabytes with no guard, and each preview tick copies all of it. The parent-chain walk that marks ReachedDetector also re-walks legs that are already flagged.

Change Cap per-thread grid memory and fall back to tiled or atomic accumulation above it; publish preview deltas rather than whole grids, and back the interval off as the run gets longer. Break the parent walk on the first already-flagged leg.

Interface

Eight findings · the physics you cannot reach
The headline

The surface editor exposes four properties — reflectance, scatter, roughness, absorption. SurfaceOptics carries roughly fifteen, including everything you built most recently: material, coating, BSDF model and parameters, volume scattering, medium priority, detector bins and acceptance angle. Materials and coatings are reachable only by editing a built-in scene's C++ or by choosing a single material at CAD import.

Nearly every accuracy feature in this report already exists in the engine and cannot be driven from the application. Closing that gap is the highest-value UI work available, and most of it is form-building against structs that already have names, ranges and tooltips written.

Gaps that block competitive parity

New capability, not deepening — scoped separately on purpose
Ray-file import

LED vendors publish measured source ray files (ASAP .dis, TracePro binary, Zemax .dat). Reading one turns "model an LED" into "use this LED". This is the single most-requested interop in illumination design and it needs no engine change — a ray file is an EmittedRay stream, and sampleEmission() is the only place that would branch.

Multiple sources

SimConfig holds exactly one source, placed by the scene. Any luminaire with more than one LED, or any system needing a stray-light source alongside the signal source, cannot be built. The tracer needs a source index on the emitted ray and a per-source power split; everything downstream already carries per-ray weight.

IES / LDT input

You can write both formats and read neither. A luminaire modelled as its measured far field is how a lighting designer composes a room, and the reader is a fraction of the writer's work.

Assembly structure

The import path uses the raw STEP reader, so product names, colours and the assembly tree are discarded. Going through XCAFDoc gives all three, and turns the flat surface list of U-02 into the tree the customer's CAD already has.

Prescription entry

No surface table — radius, thickness, glass, conic constant, aspheric coefficients. Every imaging designer starts there, and the 25 parametric scenes cannot express an arbitrary lens. An aspheric/conic revolve builder feeding the same OpticalSurface list would open the imaging market without touching the tracer.

Scripting

The 11 CLI subcommands are fixed recipes. A Python or Lua binding over optics_core — which is already cleanly separated from the widgets — would let a customer automate a study the UI does not offer, which is how these tools actually get adopted inside an engineering team.

Ordered plan

Four tiers · sequenced by dependency, not by appeal

The ordering is deliberate. Tier 1 makes the numbers defensible and builds the test scaffolding every later change needs. Tier 2 makes the physics reachable, which is where the largest gap between what you built and what a user can do currently sits. Only then does performance work pay, and only then is new capability worth adding on top.

The argument to make

Positioning

Do not compete on feature count — you will lose that comparison against tools with thirty years of accretion. Compete on the two things this codebase is already unusually good at, and which the commercial packages are conspicuously bad at.

Reproducibility. A LuxTrace run is bit-identical at any thread count, on any schedule, from a seed. That makes a regression corpus possible, makes a report's numbers regenerable, and makes an optimiser's objective a genuine function rather than something that jitters between evaluations. Most Monte Carlo tracers cannot say any of that. Tier 1 turns the property you already have into an artefact a buyer can inspect.

Honesty about uncertainty. Replica-based QMC error bars, a closed energy balance with the estimator's residual made visible rather than hidden, a Strehl figure gated by whether it means anything, a photometric export refused rather than zero-filled when the spectrum carries no luminous flux. That instinct runs through the whole codebase and it is rare. Make it visible in the interface — every number with its uncertainty, every loss channel named — and it becomes the reason someone trusts your answer over a more expensive one.
