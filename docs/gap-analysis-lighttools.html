The shape of the gap

LightTools is sold as a Core module plus twelve optional ones — Illumination, Optimization, Advanced Design, Advanced Physics, SOLIDWORKS Link, Data Exchange, SmartStart Library, Imaging Path, Imaging Analysis, Distributed Simulation, MetaOptic Design, and the AR Waveguide Designer. LuxTrace covers the Core module's ray engine and a substantial slice of the Illumination module's analysis, touches the Optimization module, and has essentially nothing from the other nine.

That is not the useful summary, though, because the modules are unevenly weighted. The honest reading is that LuxTrace is a simulator and LightTools is a design environment. LuxTrace can tell you, with a defensible error bar, what a system does. It cannot let you build most systems in the first place: twenty-six parametric tutorial scenes plus seventeen primitive object types plus a STEP importer is not a modeler, and an optic that is not a sphere, a paraboloid, a cone, a cylinder or a plane cannot be expressed at all. LightTools models plane, sphere, conic, cylinder, toroid, polynomial and anamorphic asphere, Zernike, XY polynomial, superconic, swept spline and spline patch, with unrestricted Boolean operations over all of them.

The one-sentence version

The physics gap is narrow and mostly deliberate; the modeling gap is wide and structural; the design-automation gap is the commercially decisive one. Closing physics buys credibility, closing modeling buys usability, and closing design automation is what LightTools customers actually pay for.

ParityLuxTrace does the same job to a comparable standard. Not identical UI or breadth — comparable outcome.
LeadsLuxTrace does something LightTools does not do, or does less rigorously.
PartialA working subset exists, with a documented limit that blocks real use.
GapNothing in the codebase addresses it.
Non-goalAbsent and declared out of scope in the README's model-boundary section.

Effort figures are rough engineer-months for one experienced C++/OCCT developer, to a shippable rather than a demo standard. They are estimates, not quotes.

Ray tracing engine

Where LuxTrace is most competitive on quality and least competitive on scale. Its estimator work buys error bars 1.5× to 28× tighter at the same ray count — an effect comparable to a hardware speedup — but LightTools 2026 has both, and adds distribution across machines.

Optimization and design synthesis

The commercially decisive domain. LightTools' pitch is that it will improve a design for you: "hundreds of system parameters" as variables, a weighted-sum-of-squares merit function, constraints expressed as relations on model parameters and analysis results, and — in the Advanced Design Module — geometry synthesized directly from a target illuminance or intensity pattern using LucidShape algorithms.

CapabilityLightToolsLuxTrace todayVerdictEffort
Merit function User-defined weighted sum of squares over many performance criteria A single Studies::Metric from a list of ten, with goal maximise / minimise / target. No weighting, no composition Gap 1–2 mo
Variable count and kind Hundreds of parameters, including positions and orientations of any entity Geometry parameter slots of one scene — four, or eight for a document object. Placements are not optimizable at all Gap 2–3 mo
Constraints <, =, > relations on model parameters and on analysis results (receiver total power, CIE coordinates) Box bounds on each parameter only. No relational constraints, no penalty terms Gap 1 mo

Noise-tolerant search Algorithms adapted to work in statistically noisy Monte Carlo conditions Every metric carries a standard error, and sweeps plot error bars so a bump can be told from noise. CMA-ES is intrinsically noise-tolerant Parity —
Design synthesis from a target Advanced Design Module: LucidShape algorithms construct optical geometry from a user-defined illuminance or intensity pattern None. This is inverse design, not search, and nothing in the codebase addresses it Gap 9–12 mo
Parameter sweeps Parametric studies 1D and 2D sweeps with error bars, CSV export and a UI plot Parity —
Optimizing an imported or assembled model Any entity in the model is a candidate variable Studies decline on imported CAD, because a STEP solid declares no dimensions. Read this one twice

A merit function, constraints, and placement-as-variable are the three items that turn LuxTrace's existing optimizer from a demonstration into a tool. They are roughly four engineer-months combined, they need no new physics, and they are blocked mainly by the four-double SceneParams cap. This is the highest value-per-month work in the report.

The domain LuxTrace wins outright, and the one worth building the pitch around. A commercial tool asks to be trusted on reputation; LuxTrace checks itself against arithmetic derived outside it, in CI, on every push.

What to close, in order

Ordered by value per engineer-month, not by size of gap. The tiers are sequential: each one is worth less if the one before it is skipped, because credibility gates usability and usability gates the design-automation pitch.

Tier 0

Stop the evaluator bouncing

≈ 3 engineer-months

None of these are competitive features. All of them are things a serious evaluator hits in the first session, and each one currently reads as "unfinished" rather than "scoped".

  • Persist imported CAD in the saved document. Today an import evaporates on save or on any parameter edit. Nothing else in the report is this cheap or this visible.
  • Undo / redo across the scene editor. The document model is already a flat object list with stable ids, which is close to the ideal shape for a command stack.
  • Version and migrate the config format. One field now, or a compatibility break later.
  • Equal-solid-angle far-field binning. A 1.3° beam currently falls inside a single 2° bin — the app's own flagship result is under-resolved by its own analysis.
  • Bounded receiver memory. Tile or atomically accumulate instead of one full grid per thread.
  • Logging and a crash/diagnostic dump.
  • A published cross-tool benchmark. One shared model, traced here and in a commercial tool, with the residuals printed. This converts "well tested" into "demonstrably agrees".
Tier 1

Become a modeler

≈ 8–12 engineer-months

Everything downstream is gated on being able to express the part. Aspheres first, because a conic constant and six coefficients unlock more real optics per line of code than any other geometry work.

  • Aspheric and conic surfaces — conic constant plus even-order polynomial terms, then Zernike and XY polynomial. This is a surface-generation problem in OCCT, not a tracer problem.
  • User-facing Boolean operations and sweeps on scene objects; the OCCT calls are already in SceneDocument.cpp, just not exposed.
  • Lift the parameter caps. Four doubles cannot describe a doublet; the README already names this.
  • Parametric expressions so one dimension can drive another.
  • User-defined source angular distributions, plus IES/EULUMDAT read back in as an emitter.
  • Colour-over-angle receiver maps — cheap given the spectrum machinery already there, and the metric white-LED and automotive work is specified in.
Tier 2

Become a design tool

≈ 10–14 engineer-months

This is where the product stops answering "what does this do" and starts answering "what should I build". It is also where LightTools' own module pricing concentrates.

  • A real merit function — weighted sum of squares over several criteria, on several receivers.
  • Constraints as relations on model parameters and on analysis results.
  • Placements and orientations as optimization variables, so an assembled scene is optimizable at all.
  • Ray path recording, filtering and attribution — the basis of every stray-light and ghost study, and the one analysis gap that customers name unprompted.
  • Conformal receivers on curved and freeform surfaces.
  • Surface textures — patterned micro-structures on a host surface. Large, but it is the entry ticket to backlight, display and automotive lighting work.
  • Tolerance-aware optimization: optimize expected yield, not nominal performance. Both halves already exist.
Tier 3

Pick exactly one structural bet

12+ engineer-months each

These are mutually exclusive at any realistic team size. Each defines a different product. Choosing two is how a project this size stalls.

  • Speed: GPU forward tracing, or distributed simulation as the cheap approximation of it (the JSON stdio API makes scatter/gather nearly free).
  • Appearance: backward tracing with a luminance camera and a physically-based render — the VisionSym answer.
  • Synthesis: freeform geometry computed from a target illuminance pattern — the Advanced Design / LucidShape answer, and the most defensible differentiator for a small team.
  • Physics depth: GRIN, then phosphor conversion, then gratings — in that order, since each is independently useful and phosphor is the one white-LED work actually blocks on.

Deliberately not worth chasing

  • AR Waveguide Designer. Presupposes gratings, birefringence and a luminance camera. Three modules of prerequisite for one vertical.
  • Wave propagation. Already declared out of scope, and the diffraction-limit overlay is the honest treatment. Changing this changes what the product is.
  • CATIA / NX / Parasolid translators. Licensing cost, not engineering merit. STEP covers the interchange case.
  • Sequential imaging mode and a CODE V link. A different product with different competitors; the imaging metrics already present are the right amount of imaging.
  • Thermal coupling. Out of scope and correctly so.

What to lead the pitch with

  • Every answer arrives with an error bar, estimated correctly for a low-discrepancy sequence and tested against independent seeds.
  • Bit-identical results regardless of thread count, asserted in CI.
  • Seven closed-form checks derived outside the tracer, with residuals published on every build.
  • Energy closes to 1e-9 in every scene, variance-reduction residuals included.
  • An error bar 16× tighter is 256× fewer rays — the estimator work is a speedup by another name.
  • A scriptable JSON API and a reproducible HTML report with the seed stamped on it.
